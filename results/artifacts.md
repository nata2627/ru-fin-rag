## Чего нет

| Чего нет | Что это значит для Б1 |
|---|---|
| Векторов `user-bge-m3` (1024 измерения) | выигравший гибрид `hybrid-rerank` в плотной части не поднять без пересчета корпуса. Считали на Kaggle, обратно привезли только выдачи (`data/runs/base__dense-user-bge-m3.jsonl`) |
| Векторов остальных пяти моделей | то же, пересчет на карте, по журналу части А 1322 с на T4 для `bge-m3` |
| Индекса BM25 в виде файла | индекс не сериализуется, собирается в памяти из `chunks/base.jsonl`. Замер сборки ниже |
| Модуля графа ссылок между актами | постановка (раздел 6, Б7) говорит, что он строится из `src/rufin/references.py`. На деле `references.py` снимает номера актов из текста вопроса (`strip_numbers`, `has_act_number`), графа в части А нет ни в `src/`, ни в `scripts/`. Регулярки распознавания номеров и пунктов оттуда переиспользуются, сам граф пишется с нуля |
| Публикации корпуса на HuggingFace | датасета `nata2627/ru-fin-retrieval` нет, список датасетов автора пуст (запрос к `huggingface.co/api/datasets?author=nata2627` 21.10.2026). Все `data/` части А в ее `.gitignore`, значит из публичного репозитория части А сервису брать нечего |
| Модели `deepvk/USER-bge-m3` в локальном кэше | в `~/.cache/huggingface/hub` ее нет, пересчет потребует скачать 2,1 ГБ |

Расхождение с частью А по задержке BM25: у них 0,46 мс среднее по 200 прогонам одного
запроса при k=10, здесь 1,24 мс медиана по 20 разным запросам из набора при k=50. Это разные
замеры, а не противоречие: длина запроса и k влияют напрямую.

Сжатый `chunks/base.jsonl` занимает 23 МБ (замер по готовому
`data/kaggle_out/ru-fin-base-ru-models/runs/chunks_base.jsonl.gz`), то есть корпус влезает в
репозиторий сервиса и в образ бесплатного хостинга без внешних зависимостей.
