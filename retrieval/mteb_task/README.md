# Таск MTEB

Свой бенчмарк, который прогоняется только своим кодом, это утверждение, а не
измерение. Здесь тонкая обертка, которая отдает набор библиотеке `mteb`, и
прогон чужим кодом сделан, а не обещан.

## Что измерено

Прогон 27.10.2026 на RTX 3070, `mteb` 2.26.27, модель `multilingual-e5-small`,
разделение `test` (691 запрос, все размеченное кроме dev), корпус 62 594
фрагмента скачан самой задачей с HuggingFace.

| прогон | NDCG@10 |
|---|---|
| наш код по сохраненной выдаче, те же 691 запрос | 0,42064 |
| `mteb` на опубликованном наборе | **0,42255** |
| `mteb` со склейкой `title` и `text` | 0,39183 |

Первые два числа расходятся на **0,0019**: чужой код воспроизводит наш
результат. Третья строка это та же библиотека с включенным полем `title`, и
она объясняет, почему таск его не передает.

**Про `title`.** В формате BeIR заголовок документа лежит отдельным полем, и
стандартный загрузчик склеивает его с текстом. В этом наборе заголовок акта
уже стоит внутри текста каждого фрагмента: проверено на 3 000 фрагментах,
совпало 3 000 из 3 000. Склейка добавляет к каждому документу 9,3 процента
дублирующего префикса (медианы 198 и 1 930 знаков) и стоит 0,031 NDCG@10.
Поле в наборе остается (это полезные метаданные: номер акта и название), а
таск его не передает, потому что все числа проекта считаны по тексту
фрагмента.

**Проверка опубликованного против своего.** Файлы на HuggingFace сверены с
лежащими на диске по sha256: `corpus.jsonl` (238,7 МБ), `queries.jsonl`,
`qrels/test.tsv`, `qrels/dev.tsv`, все четыре совпали.

## Как прогнать

```bash
pip install mteb
python -c "
import sys; sys.path.insert(0, 'mteb_task')
import mteb
from ru_fin_retrieval import RuFinRetrieval
model = mteb.get_model('intfloat/multilingual-e5-small')
mteb.MTEB(tasks=[RuFinRetrieval()]).run(model, output_folder='results/mteb')
"
```

Набор скачается с HuggingFace. Чтобы прогнать то, что лежит на диске, задать
`RU_FIN_RETRIEVAL_PATH=$(pwd)/data/benchmark`.

На процессоре это дорого: на маке с 8 ГБ памяти прогон уводит систему в своп
и идет больше получаса, на 3070 он занимает 4 минуты 38 секунд.

## Чего таск не делает

Таск считает одно разделение, `test`. Отдельным файлом лежит `qrels/dev.tsv`,
dev по отложенным целиком актам: он нужен обучению, а не сравнению моделей, и
в таск не включен.

Одной цифрой по `test` пользоваться нельзя: подвыборки это разные речевые
режимы (медиана длины 370, 62 и 136 знаков), и среднее по ним говорит о
смеси, которой не существует. Разбивку считает `make metrics` своим кодом по
`data/queries/podvyborki.json`, там же видно заголовочную цифру: живые,
ручные и невиданные акты без синтетики.

Осторожно с префиксами: у e5 и bge-m3 они разные, и ошибка в префиксе стоит
несколько пунктов, не давая ни ошибки, ни предупреждения. В прогоне выше
префиксы ставила сама `mteb` (`mteb.get_model` возвращает обертку, которая
знает про `query:` и `passage:`). Схемы для шести проверенных моделей лежат в
`src/rufin/retrieval/model_specs.py`.
